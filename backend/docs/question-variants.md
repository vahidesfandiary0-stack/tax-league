# نسخه‌های متفاوت سؤال در آزمون

برای هر تلاش آزمون، سرور به‌صورت مستقل:
- ترتیب سؤال‌ها را جابه‌جا می‌کند.
- ترتیب چهار گزینه هر سؤال را جابه‌جا می‌کند.
- مقادیر متغیرهای عددی سؤال را تولید می‌کند و همان مقدارها را در متن سؤال، توضیح و گزینه‌ها جایگزین می‌کند.
- نسخه تولیدشده را در AttemptQuestion و AttemptOption ذخیره می‌کند؛ بنابراین با خروج و ورود مجدد، ترتیب و اعداد همان شرکت‌کننده تغییر نمی‌کند.
- کلید پاسخ صحیح را همراه گزینه جابه‌جا می‌کند و پاسخ‌دهی/تصحیح بر اساس شناسه گزینه snapshot انجام می‌شود.

## تعریف متغیرهای عددی

در فیلد JSON با نام `variant_config` در پنل سؤال، ساختار زیر را وارد کنید:

```json
{
  "variables": {
    "amount": {"min": 100, "max": 900, "step": 100},
    "rate": {"min": 5, "max": 15, "step": 5}
  }
}
```

سپس در متن سؤال و متن گزینه‌ها از جای‌نگهدارهای ساده استفاده کنید؛ برای نمونه:

- متن سؤال: `اگر مبلغ {amount} ریال و نرخ {rate} درصد باشد، مالیات چقدر است؟`
- متن گزینه‌ها می‌تواند از `{amount}` و `{rate}` استفاده کند.
- گزینه‌ای که پاسخ درست محاسبه‌شده را نشان می‌دهد باید در پنل با `is_correct=True` مشخص شود.

مقادیر فقط عدد صحیح هستند. `min` و `max` دو سر بازه و `step` فاصله مجاز بین مقادیر است. از عبارت یا کد اجرایی دلخواه در قالب پشتیبانی نمی‌شود؛ فقط جای‌نگهدارهای نام‌گذاری‌شده مجازند.

## نکات طراحی و بازبینی

- برای سؤال محاسباتی، هر چهار گزینه باید با مقدارهای متغیر هماهنگ باشند؛ متن گزینه‌ها به‌تنهایی محاسبه یا اصلاح نمی‌شود.
- نویسنده سؤال باید بازه‌ها و گزینه‌ها را طوری طراحی کند که دقیقاً یک گزینه صحیح باقی بماند. بازبین باید چند نمونه تولیدشده را پیش از انتشار کنترل کند.
- سؤال‌های بدون `variant_config` با متن ثابت باقی می‌مانند، ولی ترتیب سؤال و گزینه آن‌ها همچنان تصادفی است.
- نسخه هر شرکت‌کننده در سرور ذخیره می‌شود و با شروع مجدد تلاش بازتولید نمی‌شود.
- تصادفی‌سازی به‌تنهایی جلوی تبادل پاسخ یا تقلب سازمان‌یافته را نمی‌گیرد؛ سیاست نظارت و تحلیل رفتار جداگانه لازم است.
