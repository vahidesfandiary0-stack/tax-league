# نقش‌ها و دسترسی کارکنان

اصل طراحی: هر حساب کارکنان باید فقط مجوزهای لازم برای وظیفه خود را داشته باشد. ساخت کارمند، فعال‌کردن `is_staff`، تخصیص گروه‌ها و مدیریت مجوزها فقط در اختیار مدیر کل (superuser) است.

پس از اجرای migrationها، فرمان زیر گروه‌ها و مجوزهای پایه را ایجاد یا به‌روزرسانی می‌کند:

```bash
python manage.py sync_staff_roles
```

## گروه‌های آماده

| گروه | دسترسی |
|---|---|
| محتوا و بانک سؤال | مشاهده/ایجاد/ویرایش سؤال و گزینه‌ها؛ انتشار و بازبینی از مسیرهای مدیریتی موجود |
| مدیر آزمون | مدیریت آزمون و ترکیب سؤال‌ها؛ مشاهده بانک سؤال |
| مسئول پرداخت | مشاهده و بررسی سفارش‌ها؛ مشاهده طرح‌ها و اشتراک‌ها |
| پشتیبان | مشاهده و تغییر وضعیت درخواست‌ها؛ مشاهده پیام‌ها و پاسخ از API پشتیبانی |
| مدیر لیگ | مدیریت فصل‌ها و مشاهده دفتر امتیاز |

تنظیمات کارت‌به‌کارت فقط برای superuser قابل مشاهده و ویرایش است. کاربران عادی هیچ‌یک از این گروه‌ها را ندارند. از اعطای مجوزهای عمومی `auth`، `accounts` یا `is_superuser` به کارکنان خودداری کنید.

## نکات اجرایی

- فقط مدیر کل می‌تواند کاربران کارکنان و گروه‌های آنان را مدیریت کند.
- کارکنان برای ورود به Django Admin باید `is_staff=True` و مجوزهای مدل مربوطه را داشته باشند.
- پس از تغییر کد نقش‌ها، فرمان sync را دوباره اجرا کنید.
- دسترسی‌های محیط عملیاتی باید با حساب‌های آزمایشی هر نقش بازبینی شوند.
