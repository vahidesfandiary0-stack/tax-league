# راه‌اندازی اتصال اشتراک کافه‌بازار

این اتصال فقط زمانی پرداخت را فعال می‌کند که سرور بتواند از API توسعه‌دهندگان کافه‌بازار توکن بگیرد و خرید اشتراک را با همان API تأیید کند. کلیدها و توکن‌ها نباید در Git، اپلیکیشن موبایل، گزارش خطا یا گفت‌وگو ذخیره شوند.

## متغیرهای محیطی سرور

این متغیرها باید فقط در فایل/مدیریت اسرار محیط Production تنظیم شوند:

- `BAZAAR_CLIENT_ID`: شناسه کلاینت API توسعه‌دهنده
- `BAZAAR_CLIENT_SECRET`: رمز کلاینت API
- `BAZAAR_REFRESH_TOKEN`: Refresh Token صادرشده از فرایند مجوزدهی API
- `BAZAAR_PACKAGE_NAME`: شناسه بسته؛ برای این برنامه `ir.raqtiva.tax_league`

## نگاشت SKU

| دوره طرح | شناسه محصول |
|---|---|
| monthly | `raqtiva_monthly` |
| quarterly | `raqtiva_quarterly` |
| annual | `raqtiva_annual` |

شناسه‌ها باید دقیقاً با شناسه‌های اشتراک ثبت‌شده در پنل توسعه‌دهندگان کافه‌بازار یکسان باشند.

## رفتار ایمن

- ساخت سفارش قبل از بازشدن صفحه پرداخت، آماده‌بودن اعتبارنامه API را بررسی می‌کند.
- تأیید نهایی فقط با پاسخ API کافه‌بازار انجام می‌شود؛ نتیجه سمت موبایل به‌تنهایی مجوز فعال‌سازی نیست.
- توکن خرید خام ذخیره نمی‌شود؛ فقط SHA-256 آن برای یکتایی و بازیابی نگهداری می‌شود.
- بازیابی فقط برای خریدی مجاز است که قبلاً به همان حساب کاربری متصل شده باشد.
- اگر تنظیمات یا سرویس تأیید در دسترس نباشد، endpoint با خطای 503 متوقف می‌شود و اشتراک فعال نمی‌شود.

## چک‌لیست قبل از فعال‌سازی

1. ثبت SKUهای بالا در پنل بازار و اطمینان از نوع Subscription بودن آن‌ها.
2. تکمیل مجوز API توسعه‌دهنده و قراردادن Client ID، Client Secret و Refresh Token در اسرار Production.
3. اجرای migration و تست‌های بک‌اند.
4. آزمون خرید و بازیابی با حساب آزمایشی بازار و بررسی تاریخ انقضا و وضعیت پرداخت در پاسخ API.
5. پس از تأیید موارد بالا، انتشار نسخه جدید اپلیکیشن و فعال‌سازی خرید.

تا قبل از تکمیل این مراحل، خرید واقعی نباید برای کاربران تبلیغ یا فعال شود.
