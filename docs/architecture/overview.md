# معماری اولیه

## سبک معماری
در فاز نخست از یک Modular Monolith استفاده می‌کنیم: یک پروژه Django با مرزبندی روشن بین ماژول‌ها. جداسازی سرویس‌ها فقط در صورت اثبات نیاز عملیاتی انجام می‌شود.

## ماژول‌ها
- accounts: حساب کاربری، احراز هویت و OTP
- questions: بانک سؤال، نسخه‌بندی و گردش بازبینی
- exams: انتشار آزمون، تلاش کاربر، ثبت پاسخ و نمره‌دهی سمت سرور
- league: فصل‌ها، دفتر امتیاز و جدول رتبه‌بندی
- payments: سفارش، رسید و بررسی دستی انتقال بانکی
- subscriptions: محصولات و دسترسی‌های اشتراک
- notifications: اعلان‌ها
- support: پیام‌های پشتیبانی درون برنامه

## قواعد امنیتی
1. کلیدها و اطلاعات محرمانه فقط در متغیر محیطی یا مخزن امن نگهداری می‌شوند.
2. API عمومی هرگز پاسخ صحیح یا فیلدهای داخلی بانک سؤال را افشا نمی‌کند.
3. زمان آزمون و نمره نهایی در سرور تعیین می‌شود.
4. انتشار آزمون یک snapshot تغییرناپذیر از سؤال‌ها و گزینه‌ها ایجاد می‌کند.
5. تغییر وضعیت پرداخت و اعطای اشتراک باید اتمیک، قابل ممیزی و محدود به نقش مجاز باشد.
6. شماره کارت فقط در تنظیمات امن پنل مدیر نگهداری می‌شود و در API عمومی قرار نمی‌گیرد.

## مراحل بعدی
1. تکمیل مدل حساب و احراز هویت
2. ساخت مسیر عمودی آزمون از شروع تا نتیجه و رتبه
3. آزمون‌های خودکار و بررسی امنیت
4. اپلیکیشن Flutter و پنل مدیریت
5. استقرار آزمایشی، آزمون بار و بازیابی پشتیبان
