# فرایند بانک سؤالات مالیاتی

## داده‌های هر سؤال
- موضوع: مالیات مستقیم، ارزش افزوده، سامانه مؤدیان، دادرسی، حسابرسی و سایر قوانین مرتبط
- سطح دشواری: آسان، متوسط یا سخت
- متن سؤال و دقیقاً چهار گزینه مرتب‌شده
- دقیقاً یک گزینه صحیح
- توضیح پاسخ و مستند قانونی
- تاریخ شروع و پایان اعتبار قانونی
- منشأ: متن رسمی آزمون، بازسازی‌شده از منبع، یا تألیفی
- نویسنده، بازبین، تصمیم بررسی، دلیل تصمیم و زمان‌ها
- شماره نسخه

## گردش کار
1. نویسنده سؤال را در وضعیت پیش‌نویس ثبت می‌کند.
2. سؤال با چهار گزینه و یک پاسخ صحیح برای بررسی ارسال می‌شود.
3. بازبین دیگری آن را تأیید یا رد می‌کند؛ نویسنده حق بررسی سؤال خودش را ندارد.
4. مدیر فقط سؤال تأییدشده را منتشر می‌کند.
5. سؤال منتشرشده و گزینه‌های آن از مسیرهای معمول مدل قابل ویرایش یا حذف نیستند. اصلاح محتوای قانونی باید با نسخه جدید انجام شود.

## حفاظت از پاسخ
- فیلد `is_correct` فقط در سمت سرور نگهداری می‌شود.
- serializer عمومی این فیلد را ارائه نمی‌کند.
- توضیح پاسخ نیز از endpoint بانک سؤال حذف شده تا پیش از پایان آزمون سرنخ پاسخ افشا نشود.
- نمره‌دهی باید صرفاً در سرور انجام شود.

## منشأ سؤال و اصالت
برچسب «رسمی» فقط زمانی انتخاب شود که سند یا مرجع قابل استناد آزمون موجود باشد. سؤال تألیفی یا بازسازی‌شده نباید به‌عنوان سؤال رسمی معرفی شود. برای هر سؤال رسمی، مرجع و اطلاعات شناسایی سند در فیلد منبع ثبت شود.

## محدودیت فعلی
این مرحله کد اولیه مدل، پنل مدیریت، سرویس بررسی و API فهرست/جزئیات را اضافه می‌کند. migration و تست‌ها هنوز در محیط واقعی اجرا نشده‌اند؛ کنترل‌های تکمیلی دسترسی، ثبت ممیزی کامل، نسخه‌سازی رسمی و آزمون‌های امنیتی پیش از بهره‌برداری لازم‌اند.
