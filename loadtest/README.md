# آزمون فشار آزمون سراسری (فقط محیط staging)

این ابزار برای شبیه‌سازی ورود شرکت‌کنندگان به یک آزمون زمان‌بندی‌شده است. هر کاربر مجازی باید توکن یک حساب آزمایشی مستقل داشته باشد.

## هشدارهای ایمنی
- هرگز روی مسابقه واقعی یا سرور production اجرا نکنید.
- از حساب‌ها، توکن‌ها و آزمون staging استفاده کنید.
- فایل `tokens.csv` محرمانه است؛ آن را commit نکنید و پس از تست حذف کنید.
- آزمون باید منتشر شده و زمان شروع آن فرا رسیده باشد.
- برای آزمایش شروع هم‌زمان، همه کاربران را در یک بازه کوتاه ramp-up کنید؛ از افزایش ناگهانی بدون هماهنگی با میزبان خودداری کنید.

## نصب
```bash
python -m venv .venv
# Windows: .venv\\Scripts\\activate
# Linux/macOS: source .venv/bin/activate
pip install -r requirements.txt
```

## آماده‌سازی توکن‌ها
یک CSV محلی با نام `tokens.csv` بسازید:
```csv
token
TOKEN_FOR_TEST_USER_1
TOKEN_FOR_TEST_USER_2
```
هر توکن باید متعلق به کاربر متفاوت و دارای دسترسی آزمون staging باشد. این فایل در Git ذخیره نمی‌شود.

## اجرا
```bash
set EXAM_ID=UUID-OF-STAGING-EXAM
set TOKENS_FILE=tokens.csv
locust -f locustfile.py --host https://staging.example.test
```
در Linux/macOS از `export` به‌جای `set` استفاده کنید. سپس در رابط Locust تعداد کاربران مجازی را حداکثر برابر تعداد توکن‌های مستقل قرار دهید و ramp-up را تدریجی تنظیم کنید.

## معیارهای ثبت‌شدنی
- نرخ خطا و پاسخ‌های HTTP 429/5xx
- p50، p95 و p99 زمان پاسخ start و answer
- CPU، RAM، اتصالات و زمان انتظار PostgreSQL
- تعداد پاسخ‌های ثبت‌شده و اختلاف آن با تعداد درخواست‌های موفق
- تأخیر نهایی‌سازی نتایج پس از deadline

قبولی ظرفیت فقط پس از اجرای آزمایش مرحله‌ای، بررسی داده‌های سرور و تکرار موفق در شرایط نزدیک به مسابقه اعلام می‌شود. این اسکریپت به‌تنهایی تضمین‌کننده ظرفیت نیست.
